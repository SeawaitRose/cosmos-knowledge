# Learning Methods

Use these methods as practical lenses during a book synthesis session. Apply only the methods that fit the user's book, goals, and energy level.

## Feynman Learning

Goal: make knowledge teachable.

Use when:

- The user can name an idea but cannot explain it simply.
- A concept sounds impressive but lacks an example.
- The book's argument needs to become usable language.

Prompts:

- "If you had to explain this to a smart 12-year-old, how would you say it?"
- "Which word in that explanation hides the most complexity?"
- "What concrete example would make this idea obvious?"
- "Where would someone misunderstand this if they only heard your summary?"

Output pattern:

- Plain-language explanation.
- Missing link or fuzzy term.
- Example from life, work, or another book.
- One review question that forces reconstruction from memory.

## Socratic Questioning

Goal: test understanding without turning the session into a quiz.

Question types:

- Clarify: "What exactly do you mean by this?"
- Evidence: "What in the book supports that?"
- Assumption: "What must be true for this idea to work?"
- Boundary: "When would this idea fail?"
- Alternative: "What would an opposing author say?"
- Consequence: "If you believed this, what would change in your behavior?"

Use 3-5 questions per round. Stop when the next question would add friction without improving the synthesis.

## Retrieval Practice

Goal: strengthen memory by recall, not rereading.

Use when:

- The user wants long-term retention.
- A book has many concepts.
- The session is becoming passive summarization.

Prompts:

- "Close the book mentally: what are the three ideas you still remember?"
- "What example can you reconstruct without looking?"
- "What question would prove you understand this idea next week?"

Output pattern:

- Add `review_questions` to each major card.
- Include at least one "explain without notes" question.
- Include at least one contrast question linking to prior knowledge.

## Spaced Repetition

Goal: create future review hooks.

Use simple intervals unless the user has a review system:

- Day 1: reconstruct the book's central model.
- Day 7: answer review questions and add one new example.
- Day 30: decide which action or belief changed.

Represent these as review prompts in the Markdown note, not as calendar reminders unless the user asks.

## Cognitive Load

Goal: prevent the knowledge graph from becoming clutter.

Guidelines:

- Prefer 5-12 strong concepts per book for first-pass extraction.
- Merge near-duplicate concepts unless their distinction matters.
- Use short node labels and put nuance in descriptions.
- Keep each card focused on one idea, not one chapter.

## Behavior Design

Goal: turn insight into usable behavior.

Use when an idea implies action.

Action extraction checklist:

- Trigger: when should the user remember this idea?
- Behavior: what small action should they take?
- Reward or feedback: how will they know it worked?
- Friction: what might stop them?
- Environment: what can be changed to make the action easier?

Output action nodes only when the behavior is specific enough to attempt within a week.

## Psychology And Brain Science

Use as synthesis lenses:

- Attention: what does the book train the user to notice?
- Memory: what should be retrieved later?
- Emotion: what feeling blocks or enables the behavior?
- Identity: what self-image does the book reinforce or challenge?
- Habit loop: cue, routine, reward.
- Prediction error: what surprised the user and updated their model?

Do not over-pathologize. Keep psychological interpretations humble and grounded in the user's words.
